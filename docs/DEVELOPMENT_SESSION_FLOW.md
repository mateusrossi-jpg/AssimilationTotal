# AssimilationTotal — Development Session Flow

This document defines how development sessions should be executed during MVP production.

The goal is to:

- maintain momentum
- avoid chaos
- reduce burnout
- create visible progress constantly
- prioritize playable results
- keep the project psychologically manageable for solo development

---

# Core Philosophy

Every work session should end with:

- visible progress
- playable progress
- clearer structure
- reduced uncertainty

Avoid sessions that create:

- giant unfinished systems
- architecture spirals
- endless refactoring
- abstract planning without execution

---

# Session Rule

Each session should focus on:

ONE major implementation target.

Examples:

- player movement
- enemy spawning
- projectile system
- Sync glitches
- fog system
- boss warning UI

Not:

"build half the game in one session"

---

# Recommended Session Structure

## Phase 1 — Define Goal

Before coding:

Answer:

"What exact visible result should exist after this session?"

Example:

"The player can move and shoot automatically."

---

# Phase 2 — Implement Smallest Version

Build the simplest functional version first.

Avoid:

- premature polish
- giant abstractions
- advanced optimization

Focus on:

- functionality
- readability
- testing

---

# Phase 3 — Quick Polish

After the feature works:

Add only minimal feel improvements.

Examples:

- hit flash
- glow
- particles
- sound
- camera shake

Small polish creates huge motivation.

---

# Phase 4 — Commit Progress

Always:

- organize files
- update docs if needed
- commit working progress

Never leave giant broken sessions.

---

# MVP Session Priorities

The highest priority sessions are:

## Gameplay

- movement
- combat
- enemy pressure
- upgrades
- Sync

## Feel

- feedback
- VFX
- atmosphere
- audio

## Identity

- UI
- lighting
- horror
- boss presentation

---

# Dangerous Session Traps

Avoid sessions that become:

## Endless Refactor

If the game is not playable yet:

DO NOT massively refactor.

---

# Tool/Framework Spiral

Avoid spending days:

- configuring systems
- changing architecture repeatedly
- chasing perfect patterns

The MVP needs momentum.

---

# Overproduction Trap

Do not:

- create dozens of enemies
- create giant maps
- create huge lore systems
- create advanced menus

Before the vertical slice exists.

---

# Solo Developer Psychology

The project must remain psychologically sustainable.

That means:

- visible progress frequently
- small achievable goals
- playable improvements often
- avoiding overwhelming complexity

# Vertical Slice Mentality

The MVP should feel:

- small
- polished
- atmospheric
- complete

Not:

- gigantic
- unfinished
- chaotic

---

# Definition Of Good Progress

Good progress is:

- a more playable game
- a more atmospheric game
- a more polished game
- a more memorable game

Not:

- bigger architecture
- more documents forever
- more theoretical systems

---

# MVP Development Goal

The project succeeds when:

- the game already feels real
- the player remembers the atmosphere
- the combat feels satisfying
- the boss feels memorable
- the Sync system feels unique

The MVP does not need massive scale.

It needs strong execution.
