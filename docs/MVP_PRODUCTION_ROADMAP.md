# AssimilationTotal — MVP Production Roadmap

This roadmap defines the official production order for the AssimilationTotal MVP.

The goal is to:

- maintain focus
- avoid scope creep
- reduce burnout
- prioritize playable progress
- reach a polished vertical slice quickly

---

# Core Production Rule

MVP first.
Atmosphere over scale.
Polish over quantity.

The first goal is NOT:

- huge content
- multiple maps
- giant lore systems
- advanced features

The first goal is:

"Create a small but memorable playable sci-fi horror experience."

---

# Production Philosophy

Every implementation decision must answer:

"Does this help the MVP become playable, atmospheric, and memorable faster?"

If not:

Backlog.
Later.

---

# MVP Definition

The MVP is successful when:

- the game is playable
- combat feels satisfying
- the atmosphere feels oppressive
- the Sync system feels interesting
- the first boss feels memorable
- the game already has strong identity
- the game runs on Android

---

## Goal

Create the first playable combat prototype.

---

# Tasks

- health
- damage
- death
- XP
- level up

## Enemy

- spawn

- take damage
- die

- XP pickups

- fight

- level up

---

# Android Production Rules

The project is Android-first.

Always prioritize:

- performance
- readability
- scalable VFX
- lightweight systems
- touch usability

Avoid:

- massive particle spam
- extremely expensive shaders
- giant textures
- unnecessary CPU-heavy systems

---

# Anti-Scope Rules

Do NOT implement before MVP:

- multiplayer
- inventory
- skill trees
- crafting
- dialogue system
- giant story systems
- procedural world generation
- multiple maps
- multiple bosses
- online systems
- shops/monetization
- cosmetics
- cloud saves

---

# MVP Emotional Goal

The player should finish the MVP thinking:

"This feels like a real atmospheric sci-fi horror game with strong identity."

Not:

"This feels like another generic survivors clone."

That difference is the entire production strategy.
