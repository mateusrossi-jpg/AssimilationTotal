# AssimilationTotal — Mobile Controls Direction

AssimilationTotal is Android-first.

Mobile controls must be treated as a core design pillar, not an afterthought.

The game must feel playable, readable, and comfortable on a smartphone screen.

---

# Core Mobile Philosophy

The player should control movement only.

Combat should be automatic.

This keeps the experience:

- fast
- readable
- accessible
- suitable for one-handed or casual mobile play
- aligned with survivors-like design

---

# MVP Control Scheme

## Movement

Virtual joystick on the bottom-left side of the screen.

## Attacks

Automatic.

Weapons target enemies automatically.

## Upgrades

Tap upgrade cards during level-up.

## Pause

Small pause button in the top-right corner.

---

# Why Auto-Attack

Auto-attack is important because it allows the player to focus on:

- positioning
- dodging
- collecting XP
- survival
- reading enemy pressure
- making upgrade choices

Manual aiming should not be part of the MVP.

---

# Touch UX Rules

Controls must be:

- large enough for thumbs
- visually clear
- non-intrusive
- responsive
- readable over dark backgrounds

Avoid placing critical UI near the movement joystick.

---

# Screen Layout — MVP

## Bottom Left

Virtual joystick.

## Bottom Center

XP bar.

## Top Left

Health bar.

## Right Side

Sync meter.

## Top Right

Pause button.

## Center Screen

Gameplay only.

Avoid UI clutter in the combat area.

---

# Mobile Readability Rules

Because the screen is small:

- enemy silhouettes must be clear
- projectiles must be readable
- VFX must not hide threats
- UI text must be minimal
- high contrast is mandatory

---

# Visual Touch Feedback

The player should receive immediate feedback from:

- joystick activation
- upgrade card selection
- pause button tap
- damage received
- low health warning
- boss warning

---

# Joystick Visual Direction

The joystick should match the game identity:

- dark transparent base
- neon yellow outline
- subtle holographic glow
- minimal animation

Avoid cartoon-style mobile controls.

---

# Upgrade Selection UX

Upgrade cards must be:

- large
- readable
- easy to tap
- clearly separated
- visually distinct by rarity

The player should make choices quickly without reading long text.

---

# Boss Warning UX

When the boss appears:

- center warning overlay
- screen darkens slightly
- warning sound
- red/yellow alert lines
- boss name appears

Must be readable on mobile.

---

# Performance Rules For Mobile

Mobile controls and visuals must avoid:

- excessive screen clutter
- huge particle overload
- tiny UI elements
- complex simultaneous inputs
- precision aiming requirements

---

# MVP Mobile Goal

The MVP succeeds if the player can:

- move comfortably
- understand threats
- collect XP easily
- select upgrades quickly
- enjoy combat without aiming manually

The controls should disappear from the player's attention after a few seconds.
